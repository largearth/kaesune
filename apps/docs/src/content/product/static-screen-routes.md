# 静的画面とルーティング

モバイルを主対象とした静的な UI 実装として、次の画面を提供する。データ取得、認証、支払いの保存・請求発行は含めず、各画面遷移と表示のみを扱う。

| URL                        | 画面                   | 主な遷移先・役割                               |
| -------------------------- | ---------------------- | ---------------------------------------------- |
| `/`                        | ID・パスワードログイン | `/home`                                        |
| `/home`                    | ホーム                 | 記録一覧、立替記録、マイページ                 |
| `/records`                 | 出金記録               | 記録の確認、後続の負担決定                     |
| `/payments/new/allocation` | 負担を決定する         | 記録済み出金を確認して行う後続操作             |
| `/invoices`                | 請求一覧               | 決定済みの負担をもとに扱う請求・精算状況の確認 |
| `/mypage`                  | マイページ             | 財布管理、グループ                             |
| `/wallets`                 | 財布管理               | 下部ナビゲーション                             |
| `/group`                   | グループ               | 下部ナビゲーション                             |

## 共通 UI

ログイン画面と立替記録・負担決定の操作画面を除く画面には、ホーム・レコード・インボイスへ移動できる3項目の下部ナビゲーションを表示する。マイページは Home のユーザーアイコンから開く。

立替記録はホーム画面の「立て替えたお金を記録する」から全画面ダイアログで行う。出金元財布・金額・用途などの事実だけを保存し、保存時に負担するユーザーや負担額を決めず、請求も確定・生成しない。

記録済みの出金は後から確認し、必要な時点で負担決定へ進める。負担決定と請求は記録とは別の後続操作であり、記録時に請求を確定・生成しない。請求を扱い始める具体的な操作・画面構成、CTA、詳細遷移、URLの見直しはこの静的画面仕様の更新では定めない。

## フロントエンド構成

- `apps/web/src/router.tsx`: URL と画面コンポーネントの対応を管理する。
- `apps/web/src/pages/`: 画面単位のページコンポーネントを配置する。
- `apps/web/src/components/`: 画面間で共有する UI、レイアウト、支払い一覧を配置する。
- `apps/web/src/data/`: 静的画面で共有する支払いデータを配置する。
- UI スタイルは Tailwind CSS のユーティリティクラスで管理する。

## ビジュアル方針

Home の改訂デザインを全画面の基準とする。白地に黒の文字・罫線・CTA を置き、アクセントとしてグリーンを使用する。下部ナビゲーションはホーム、レコード、インボイスの3項目で統一する。
